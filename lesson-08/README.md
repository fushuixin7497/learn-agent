# 🎛️ 模块 8：Permission Models —— 安全-效率光谱上的权限模型

## 一、这个任务在干什么？

模块 7 给 Agent 装上了最小权限的"门"：副作用操作要确认，危险操作永远禁止。但马上会遇到一个新矛盾：

> **每次调用都问用户，最安全，但 Agent 跑一个任务要打断十几次；全自动最高效，但出事没人把关。**

真实系统（包括 Kimi Code、Claude Code 等）的答案不是二选一，而是提供一条**可调节的光谱**，让用户按任务的风险程度选档位：

```
per-call confirm → session allowlist → auto（两级分类器）→ YOLO
   最安全 ←──────────────────────────────────────→ 最高效
```

本课目标：用**一个统一入口 + 四种模式 + 一份审计日志**，实现这条光谱。

核心代码只有一个文件：`permission_models.py`（纯标准库，约 300 行）。

---

## 二、安全-效率光谱：四种模式

| 模式 | 行为 | 适用场景 |
|---|---|---|
| **CONFIRM** | 每个副作用调用都问一次用户 | 生产环境操作真实数据 |
| **ALLOWLIST** | 用户批准一次，该工具**本会话**内不再询问 | 稍长但仍需谨慎的会话 |
| **AUTO** | 两级分类器自动判断（fast path → slow path + 15s 超时） | 日常开发的主力模式 |
| **YOLO** | 全部放行 | 隔离环境 / 一次性脚本 |

两个横切原则，贯穿所有模式：

- **危险工具永远禁止**：`execute_shell` / `delete_file` / `send_email` 在任何模式下都被拒绝 —— 放宽效率不等于开放不可逆操作。
- **每个决定都进审计日志**：谁决定的（用户 / 规则 / 分类器 / 失败策略）、依据什么、耗时多少，全部可追溯。

---

## 三、重点拆解：AUTO 模式的两级分类器

AUTO 是这条光谱上最有技术含量的一档，设计目标是**既不用频繁打扰用户，又不把判断完全交给黑盒**。

### 第一级：fast path（廉价规则，零延迟）

满足一组严格条件的调用直接放行，不调用任何模型：

- 工具本身是只读的（`calculator` / `read_file` …）
- 或者是**工作目录内的小写入**：路径在 `workdir` 内 + 内容大小受限（防大 payload 注入绕过）

命中 fast path 的决定耗时 ~0ms，绝大多数日常调用止步于此。

### 第二级：slow path（复杂分类器，15s 超时兜底）

fast path 没命中 → 交给可插拔的 `classifier`（生产中是 LLM 判断"这次调用是否安全"，这里是教学用启发式函数）。它有两个保护：

1. **15 秒超时**：分类器卡住不能拖死 Agent。
2. **可配置失败策略**（failure policy）：超时或异常时——
   - `fail_closed`（默认，安全优先）：拿不准就**拒绝**；
   - `fail_open`（效率优先）：拿不准就放行（应配合沙箱）。

```
调用进入 AUTO
   │
   ├─ fast path 命中？──是──→ ALLOW（规则放行）
   │
   ├─ slow path 分类器（≤15s）
   │      ├─ 返回 ALLOW/DENY ──→ 按结果执行
   │      ├─ 返回 ASK ────────→ 转人工确认
   │      └─ 超时 / 异常 ─────→ failure policy：fail_closed → DENY
   │                                        fail_open   → ALLOW
```

### 为什么要"失败策略"这个设计？

权限系统的失效方向是一个明确的安全姿态声明：银行场景宁可误拒不可误放（fail-closed）；隔离沙箱里的批处理宁可跑完不可卡死（fail-open）。**默认永远 fail-closed** —— 效率模式必须显式选择。

## 四、运行与输出解读

```bash
python3 permission_models.py
```

脚本把**同一批工具调用**依次放在光谱四个档位上跑，然后单独演示失败策略。关注三个对比：

1. **CONFIRM vs ALLOWLIST**：注意第二个 `write_file` —— CONFIRM 下又问了一次，ALLOWLIST 下直接 `by=session_allowlist` 放行。这就是"会话白名单"省掉的打断。
2. **AUTO 的审计日志 `by=` 列**：`fast_path` / `slow_path` / `user` 一目了然 —— 你可以精确回答"这次放行是谁拍的板"。
3. **失败策略演示**：把分类器模拟成 2 秒才返回、超时设为 0.5 秒，两种策略给出相反的决定，且原因写进了审计日志。

典型输出片段（AUTO 模式）：

```
[ALLOW] calculator      by=fast_path    0.0ms  只读工具，规则直接放行
[ALLOW] write_file      by=fast_path    0.0ms  工作目录内的小写入，规则直接放行
[ASK  ] write_file      by=slow_path    0.1ms  分类器不确定，转人工确认
[DENY ] execute_shell   by=catalog      0.0ms  危险工具，任何模式下都禁止
```

## 五、与其他模块的关系

- **模块 7**：提供了"哪些工具危险"的分类（本课直接复用了它的思路：`SAFE / SIDE_EFFECT / FORBIDDEN`）。模块 7 解决"**能不能做**"，本课解决"**谁来决定能不能做**"。
- **后续可扩展**：
  - `classifier` 换成真实 LLM 调用，slow path 就是生产级实现；
  - 审计日志持久化到文件，即可做事后审计与回放；
  - 把模式选择做成 CLI flag（如 `--permission auto`），用户在启动 Agent 时选档位。
